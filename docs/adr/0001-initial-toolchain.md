# ADR-0001: Initial Toolchain

## Status

Accepted

## Context

The Cornell Smart Parking Availability and Recommendation System requires an initial development environment for implementing the parking recommendation service and its LLM-supported user interaction.

The application is expected to use Python for data processing and backend development. The LLM will initially be used to explain recommendation results and answer user questions rather than perform the core parking ranking logic.

The team does not currently have a paid cloud API key, and the primary development computer is a Mac with 16 GB of memory and 512 GB of storage. Therefore, the initial toolchain should minimize cost, hardware usage, and setup complexity while remaining suitable for future integration with FastAPI.

## Decision

- Language: Python 3.12
- Runtime: Local Python virtual environment
- Model hosting: Local for initial development and demonstration
- Model runner: Ollama
- Model: Qwen3 4B as the initial baseline
- Containerization: Not currently required
- Editors: PyCharm and Visual Studio Code

## Rationale

Python was selected because it supports the planned FastAPI backend, data processing, recommendation logic, and LLM integration. A local virtual environment provides sufficient dependency isolation for the current project stage without introducing the additional configuration and memory overhead of Docker.

Local model hosting avoids the immediate need for a paid API key, eliminates per-request API costs, and allows development without depending on an external service. Ollama was selected as the initial model runner because it provides a straightforward installation process on macOS and exposes a local HTTP API that can be called by the FastAPI application.

Qwen3 4B was selected as the initial baseline because it has relatively modest storage and memory requirements and is more appropriate for a Mac with 16 GB of memory than larger models. The model will primarily explain parking recommendations generated by deterministic application logic, so a large model is not required for the initial prototype.

Docker is deferred because the current repository is an early-stage course project and can be reproduced using a Python virtual environment and `requirements.txt`.

## What Would Change This Decision

The team will reconsider this decision if testing shows that Qwen3 4B does not provide sufficiently accurate or understandable responses. In that case, the team may evaluate Qwen3 8B or a hosted model API.

The team may move from local to hosted model deployment if local inference is too slow, consumes too much memory, or prevents the application from being deployed as a publicly accessible multi-user service.

The runtime or Python version may also be changed if required dependencies are incompatible with Python 3.12. Docker may be introduced later if cloud deployment, multiple supporting services, or reproducible cross-platform execution becomes necessary.
